# 凛冬要塞 v5.0.0 — 大版本规划（可玩性扩展）

> 规划人：游戏设计师
> 日期：2026-07-31
> 前置状态：v4.2.2 三轮评审修复全部闭环（343 测试全绿）
> 规划原则：**先补地基再盖楼。所有新增内容不得绕过既有防线（GAMESTATE 协议、dispatchAction 队列、Zod 校验、[PLACEHOLDER] 数值纪律）。**

---

## 零、前提核查：可玩性的真正短板在哪

规划前对当前代码做了地基体检，结论必须先摆出来——**这个项目现在"数值轨道通了电，但玩家没有"性命"**：

| 检查项 | 实测结果 |
|--------|---------|
| HP/MP 数值池 | ❌ 不存在。`handleUseItem` 显示"❤️ HP +30"只是文案；战斗伤害不扣任何血 |
| 死亡豁免（wr-death-save） | ❌ 死规则。规则写在 worldRules 里，前端无 HP 无从触发 |
| 死亡/失败惩罚 | ❌ 无。玩家永远不会死 → 战斗无风险 → 装备/药剂/治疗/防御值全部失去意义 |
| 纪元结构（wr-time-epoch） | ❌ 死规则。"四纪元"只有名字，时间只是计数器 |
| 职业机制（24 个） | ⚠️ [PLACEHOLDER]，叙事层生效 |
| 结局评估节奏 | ⚠️ 每 30 天一次（30 轮对话），无进度可见性 |

**判断**：可玩性提升的第一优先不是"新增内容"，而是把"死亡/损失/成长"这条压力链补上。没有 HP 的 RPG 里，加再多敌人和装备都是表演。以下规划以此为纲。

**Fun Hypothesis 更新**：在"叙事自由 + 数值成长 + 世界因果"之上，增加第三支柱——**压力感（Stakes）**：玩家会受伤、会濒死、会失去；每一次数值决策都在为"活下来并赢下纪元"服务。

## 一、新增功能模块设计方向（4 个模块，按地基/结构/内容/留存分层）

### 模块 A：健康系统落地（P0 地基，第 1-2 周）

**目的**：给所有"数值表演"装上真实的结算器。

**设计**：
- **HP/MP 池**：`playerVitals: { hp, maxHp, mp, maxMp }`，公式用既有设定：`maxHp = 50 + CON×15`，`maxMp = 20 + INT×10`（settings-loader attributes 已有，落地即可）
- **伤害闭环**：`resolveCombat` 结果 → `hp -= damage` → 归零触发死亡豁免
- **死亡豁免**：复用 CheckDiceOverlay 的 D20 动画——HP 归零弹"死亡豁免"遮罩，`D20 + (CON-5) ≥ 10` 成功；三成功稳定、三失败「陨落」结局（接入结局系统）；每次豁免后追加永久伤痕（伤病因系统已有 state，接入）
- **恢复**：旅馆休息/休整恢复 HP/MP；治疗药剂真正扣减背包并加血
- **敌人也有 HP**：`enemyHp = f(区域危险度, 天数)`，攻击多次才击杀——"几刀杀敌"成为可调曲线

**数值 [PLACEHOLDER]**：敌人数值曲线 `enemyHp = 30 + dangerLevel×15 + floor(day/10)×5`，验证路径：打 20 场不同区域战斗，记录"平均几刀杀敌"目标 3-5 刀。

**验收**：玩家 HP 归零必须弹出豁免；豁免失败三次必须进结局；药剂必须实际回血。

### 模块 B：纪元结构（P0 结构，第 3-4 周）

**目的**：把"时间计数器"变成"剧情节拍器"，解决 30 天结局评估的节奏空洞。

**设计**：
- 四纪元：孤守要塞 → 联合诸族 → 光暗交锋 → 命运终局，由主线阶段驱动（阶段 1-2 / 3 / 4 / 5）
- 纪元推进 = 章节边界：触发"纪元终结事件"（AI 生成总结 + 前端结算），**checkEnding 从"每 30 天"改为"每纪元终结 + 关键节点"**——玩家每 1-2 小时就有一次结局进度反馈
- 每纪元解锁内容：纪二解锁阵营外交线、纪三解锁地下城、纪四进入终局锁定（不可再自由探索）

**验收**：单局 4-6 小时跑完四纪元；每纪元末玩家能看到结局进度变化。

### 模块 C：战斗轮状态 + 职业机制机制化（P1，第 5-6 周）

**目的**：兑现 24 个职业机制的存量资产。

**设计**：
- 轻量"战斗轮"：`combatRound` ref，进入战斗（关键词触发）后每轮 +1，对话中"我撤退/我收剑"或非战斗指令重置——**不引入完整回合制**，只提供机制需要的轮数上下文
- 首批接入 3 个高频机制（其余标 [PLACEHOLDER] 不假装）：
  - 战士·怒气爆发：onHit 累积 3 次 → 下次伤害 +30%（在 resolveCombat 前检查 combo）
  - 刺客·背刺暴击：输入含"潜行/背刺/影步"且未被打断 → 必暴击
  - 法师·法力护盾：HP 低于 30% 时，MP 可抵一次致命伤害（每场一次）
- 机制触发走**前端裁决**（AI 只演绎），与检定/战斗结果同一注入通道

**验收**：3 个职业各跑通一次机制触发，战斗日志明示机制生效。

### 模块 D：roguelite 地下城容器（P2 内容工厂，第 7-10 周）

**目的**：给"内容扩展"一个可持续的容器——文字冒险最自然的可重玩内容形态。

**设计**：
- 危险度 ≥ danger 的区域（阴影山脉/荒芜平原/黑曜石荒原/龙脊冰峰）解锁「深入探索」→ 生成 3-5 层小型地城：每层 AI 生成场景 + 前端掷骰/战斗判定 → 层末奖励宝箱
- **crystal 是地下城的专属产出**（顺带解决领地 3 级建筑的晶体 source 缺口——现在是 AI 协议手动发，地下城给一个稳定获取通道）
- 失败（HP 归零）→ 损失已拾取战利品 + 永久伤痕，强制回城——**这就是"可重玩"的引擎：风险/回报决策**
- 地城词缀化：每层 1 个随机修饰（黑暗/霜寒/亡灵涌动…）进 prompt

**验收**：通关一次地城获得 ≥1 件 rare+ 装备 + ≥2 晶体；失败损失战利品。

## 三、可玩性优化策略

1. **难度曲线成型**：危险度（safe→deadly）→ 敌人 HP/伤害 → 掉落品质，一条数值链打通。目标：凛冬谷新手区 2-3 刀杀敌、龙脊冰峰 5-7 刀且吃 2 次以上重伤——玩家能"感知到危险"。
2. **结局进度可见性（还账）**：结局面板显示 8 结局条件达成度百分比 + 当前主线阶段/纪元。上一轮欠的账，这轮必须还。
3. **死亡豁免 UI + 永久伤痕**：濒死是高光时刻，不是黑屏。伤痕显示在角色面板（"左臂旧伤：敏捷检定 -1"）——让失败也有记忆。
4. **声望解锁内容**：声望门槛（30/60）解锁商人折扣、专属任务、同伴专属技能——声望从"数值"变成"钥匙"。
5. **成就系统完善**：进度条（探索 3/6）、隐藏成就（达成后揭示）、**技能点渠道扩展**（地下城通关 +1、纪元完成 +2——解决技能点永久枯竭的最后一环）。
6. **社交钩子：领主战报**：扩展已有对话导出为"战报"模板（天数/结局/击杀/声望/领地/成就徽章/关键抉择），一键复制分享——单机文字游戏最实际的社交形态。

## 四、优先级排序与实施节奏

| 里程碑 | 内容 | 时长 | 验收标准 | 回归风险 |
|--------|------|------|---------|---------|
| **M1 地基** | 模块 A：HP/MP/死亡豁免/敌人 HP | 2 周 | HP 归零弹豁免；豁免失败进结局；药剂真回血 | **最高风险**：动 handleUseItem/resolveCombat/装备公式——必须与 PlayerCombatStats 一并重构，新增 GAMESTATE 字段（hp/mp）向后兼容，测试先行 |
| **M2 结构** | 模块 B：纪元 + 结局评估重构 | 2 周 | 四纪元跑通；结局进度 UI 上线 | checkEnding 改造不得破坏堕落 100 即时湮灭 |
| **M3 内容** | 模块 C + 新区域/NPC/词缀/地城 | 3-4 周 | 3 职业机制生效；地城通关有稳定产出 | 地城掉落必须走 GAMESTATE 协议；crystal 产出与 AI 手动发不冲突 |
| **M4 留存** | 成就完善/战报/节日/新结局 | 2 周 | 技能点有新渠道；战报可一键分享 | 新结局注册进 ending-system 优先级表，不与既有结局冲突 |
| **M5 打磨** | 全量平衡 pass + 难度曲线调参 | 1-2 周 | 全区域"几刀杀敌"达标；343+ 测试全绿 | 调参只动 [PLACEHOLDER] 数值，不动协议 |

**节奏原则**：M1-M2 是"可玩性"的地基，不做完不进 M3——**在没有死亡威胁的游戏里加内容，等于给表演加道具**。

## 五、回归风险控制清单（强制项）

1. **协议向后兼容**：GAMESTATE 新增 hp/mp/enemyHp 字段必须是 optional 增量，旧 AI 响应不带这些字段不报错（Zod partial 已支持）
2. **所有玩家操作仍走 dispatchAction**：地下城/鉴定/战报等新交互不得自建 setTimeout+click，必须收敛进队列
3. **数值纪律**：本规划所有新数值均为 [PLACEHOLDER]，附验证路径（打 X 场/跑 Y 局），不经 playtest 不进正式值
4. **测试先行**：每个模块先写接线层测试（吸取 R1-R3 教训：纯函数层测试抓不到接线 bug），再写实现
5. **跨会话状态**：新增的跨会话 ref/state（地下城进度、豁免计数）一律进 gameState 随存档走，杜绝 R7 类状态丢失
6. **每里程碑独立可玩**：M1 结束时玩家能"受伤-濒死-豁免-恢复"完整闭环，M2 结束时玩家能"打一纪-看进度-等终局"——不做半成品集成
