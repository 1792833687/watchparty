## 1. 核心支柱 (Design Pillars)

> **支柱是不可妥协的设计原则。所有后续设计决策必须以支柱为检验标准。**

---

### 支柱 I: AI 即游戏主持人 (AI as Game Master)

> "AI 不是故事生成器，而是桌游主持人。"

- AI 主动引导剧情走向，非被动响应玩家输入
- AI 拥有"上帝视角"的世界状态感知，能创造偶遇、突发事件、隐藏线索
- AI 在必要时说"不"——维护世界规则的边界，不让玩家为所欲为
- 对话自由度与叙事约束的平衡：玩家自由表达，AI 负责在规则框架内将其翻译为有意义的游戏动作

**设计红线**：绝不退化为"无限制的 AI 聊天机器人"。AI 始终戴着"GM 的帽子"工作。

---

### 支柱 II: 地图即叙事 (Map as Narrative)

> "地图不是装饰。地图是叙事引擎。"

- 2.5D 地图的每一个图块都是潜在的叙事触发器——不是背景，是界面
- 空间关系编码叙事关系：距离代表情感或政治距离，不可达区域代表未知与悬念
- 地图状态随时间与玩家行为演化：被烧毁的村庄不会自动恢复，NPC 会移动
- 玩家在地图上的位置影响 AI 的叙事生成（上下文注入：当前区域、邻近 POI、区域历史）

**设计红线**：杜绝"装饰性地形"——每个区域必须承担至少一个叙事、机制或资源功能。

---

### 支柱 III: 记忆即世界 (Memory is the World)

> "被遗忘的事件等于从未发生。"

- 独立的记忆引擎是所有叙事连续性的唯一来源——不依赖 LLM 的上下文窗口
- 三层记忆架构：即时记忆（当前会话上下文）、短期记忆（最近几次会话的关键事件摘要）、长期记忆（持久化的世界状态、角色关系、关键决策）
- 记忆引擎自动从游戏日志中提取实体、关系、事件，构建可查询的世界状态图谱
- "遗忘"是一种具有叙事意义的设计选择——某些实体可能因魔法、时间或刻意隐藏而不可回忆

**设计红线**：绝不依赖"把整个历史塞进 prompt"的暴力方案。记忆引擎是独立子系统，LLM 是消费者而非存储者。

---

### 支柱 IV: 玩家选择有重量 (Choices Have Weight)

> "每一个选择都在世界中留下不可逆的痕迹。"

- 所有关键决策都记录在世界状态中，不可撤销、不可回滚（除非世界规则允许，如时间魔法）
- 选择产生连锁反应：帮助一个 NPC 可能得罪另一个，打开一扇门可能释放某种力量
- 玩家必须承担选择的后果——没有"最优解"，只有"不同的故事"
- 结局不是预设的，而是在世界状态中涌现的——AI GM 在最终章汇总所有关键决策，生成独一无二的结局

**设计红线**：杜绝"假选择"（不同选项导向相同结果）。如果 UI 上给了三个选项，世界状态中至少有三个可区分的结果分支。

## 2. MDA 分析

### 2.1 Mechanics（机制层 — 规则与系统）

| 类别 | 具体机制 | 说明 |
|------|---------|------|
| **空间探索** | 2.5D 图块点击导航 | 玩家点击地图上的可达图块移动角色，移动触发区域事件 |
| **对话交互** | 自由文本输入 + 建议动作 | 玩家可自由输入，也可从 AI 生成的建议中选择；AI 以 GM 身份回应 |
| **状态系��** | 角色属性（HP/MP/理智/声望等）、背包、技能 | 由游戏设定文件定义属性维度；数值影响叙事可行性（如力量检定） |
| **记忆引擎** | 自动实体提取 → 关系图谱构建 → 上下文检索 | 三个子系统独立运作：提取器、图谱管理器、检索器 |
| **世界书** | 从游戏设定自动生成的 lore 一致性层 | 包含地点、派系、人物、历史事件、魔法规则等结构化条目 |
| **时间系统** | 游戏内时间推进（休息/旅行/等待触发） | 时间影响 NPC 行为、事件触发、世界状态 |
| **存档系统** | 世界状态完整快照 + 记忆图谱 | 每次存档保存完整游戏状态，支持多存档位 |
| **游戏设定管理** | AI 生成或导入自定义设定文件 | 设定文件定义世界规则、种族、职业、初始状态 |

---

### 2.2 Dynamics（动态层 — 玩家行为涌现）

| 动态模式 | 描述 | 驱动机制 |
|---------|------|---------|
| **探索驱动** | 玩家受好奇心驱使探索地图未知区域 | 战争迷雾、区域解锁条件、隐藏 POI |
| **叙事涌现** | 每次游戏产生独一无二的故事线 | AI GM 根据世界状态 + 玩家行为实时生成 |
| **关系博弈** | 与 NPC/派系的关系管理成为策略核心 | 关系值系统、派系声望、信任门槛 |
| **资源紧张** | 有限的资源迫使玩家做出取舍 | 背包容量、金钱、时间压力 |
| **信息不对称** | 玩家掌握的信息始终不完整，需要通过探索/对话获取 | 记忆引擎的检索边界、NPC 知识的有限性 |
| **长程因果** | 早期决策在后期产生意外后果 | 记忆引擎的因果追踪 |
| **空间叙事** | 地图布局本身讲述故事 | 区域设计、不可达区域、地形隐喻 |

---

### 2.3 Aesthetics（体验层 — 玩家情感目标）

| 美学类型 (MDA 8类) | 本游戏映射 | 实现方式 |
|---------------------|-----------|---------|
| **Sensation（感官）** | 2.5D 视觉沉浸、音景氛围 | 等距地图 + 环境音效 + 视觉特效 |
| **Fantasy（幻想）** | 成为奇幻世界的主角 | AI GM 将玩家置于故事中心 |
| **Narrative（叙事）** | 体验独一无二的个人传奇 | 涌现式叙事 + 个性化结局 |
| **Challenge（挑战）** | 解谜、战斗、策略决策 | GM 设计的遭遇战与谜题 |
| **Fellowship（社交）** | 与 NPC 建立深厚羁绊 | 记忆引擎的关系追踪 |
| **Discovery（发现）** | 揭开世界秘密 | 探索 → 线索 → 真相 链条 |
| **Expression（表达）** | 通过选择塑造角色与故事 | 无职业限制的角色发展 |
| **Submission（消遣）** | 放松的探索模式 | 安全区域、日常互动 |

**核心美学权重**（从高到低）：Narrative > Discovery > Fantasy > Expression > Fellowship

## 3. 范围分层 (Scope Layers)

### Must Have — MVP（最小可行产品）

| 编号 | 功能 | 验收标准 |
|------|------|---------|
| M01 | 2.5D 地图图块渲染与点击导航 | 玩家可点击可见图块移动角色，移动有动画过渡 |
| M02 | AI GM 对话核心循环 | 自由文本输入 → AI 回应 → 状态更新 → 等待下一次输入 |
| M03 | 对话建议动作生成 | AI 在每次回应后提供 2-5 个建议的下一步动作 |
| M04 | 基础记忆系统（即时 + 短期） | 同一会话内剧情连贯；关闭重开后能回忆起上次的关键事件 |
| M05 | 角色创建与基础属性 | 至少包含姓名、外观描述、3 项基础属性 |
| M06 | 基础 HUD（状态栏 + 对话面板 + 小地图） | 三个面板同时可见，信息清晰不遮挡 |
| M07 | 游戏设定加载（至少 1 个预设 + 导入功能） | 预设设定可玩通一个短故事；导入功能接受 JSON/YAML |
| M08 | AI 生成游戏设定 | 输入 prompt → AI 产出完整游戏设定文件 |
| M09 | OpenRouter LLM 接入与模型切换 | 支持至少 3 个模型（如 GPT-4o、Claude 3.5 Sonnet、Gemini 1.5 Pro） |
| M10 | 基础存档/读档 | 保存完整世界状态，支持 3 个存档位 |

---

### Should Have — 目标版本

| 编号 | 功能 | 说明 |
|------|------|------|
| S01 | 长期记忆持久化（跨多会话） | 基于向量检索的世界状态查询 |
| S02 | NPC 关系图谱可视化 | React Flow 展示角色关系网 |
| S03 | 背包与物品系统 | 物品可获取、使用、丢弃；物品影响叙事 |
| S04 | 世界书可视化浏览器 | 玩家可浏览已解锁的世界条目 |

| S07 | 多游戏设定模板 | 至少 3 个风格不同的预设设定（奇幻、科幻、恐怖） |
| S08 | 对话历史回滚与分支回顾 | 玩家可查看过去的对话分支 |

### Could Have — 愿景版本

| 编号 | 功能 | 说明 |

### Won't Have — 明确不做

| 编号 | 功能 | 理由 |
|------|------|------|
| W01 | 多人实时在线 | 与"单人叙事体验"定位冲突 |
| W02 | 3D 自由视角 | 2.5D 等距是核心视觉锚点 |
| W03 | 实时动作战斗 | 与回合制/叙事驱动节奏冲突 |
| W04 | 程序化地图生成 | 手绘地图承载叙事意图，程序化生成稀释叙事密度 |
| W05 | 语音输入 | MVP 阶段文本输入足以验证核心体验 |
| W06 | 手机端 | MVP 聚焦桌面端 Web 体验 |

## 4. 视觉锚点 (Visual Anchors)

> 以下三个视觉参考为美术团队（林绘澄）提供风格方向。不是最终美术方案，而是设计愿景的可视化锚点。

---

### 锚点 A: 等距 2.5D 地图 — "会呼吸的桌游棋盘"

**参考作品**: *Disco Elysium* 的等距视角 + *Octopath Traveler* 的 HD-2D 光影 + 桌游微缩模型质感

**核心视觉元素**:
- 等距视角（约 30° 俯角），图块网格清晰但不生硬
- 柔和的动态光照：昼夜循环、天气粒子（雨/雪/雾）、光源扩散
- 地貌具有"手工打造"的质感——不是照片写实，而是风格化的微缩景观
- 地图边界不做硬性切割，而是用"迷雾"或"未渲染的铅笔草图"过渡
- 交互图块有微妙的发光/呼吸动画，暗示"这里可以点击"

**情绪关键词**: 温暖、神秘、触手可及、探索欲

---

### 锚点 B: 对话交互面板 — "故事之窗"

**参考作品**: *Visual Novel* 对话框 + *Divinity: Original Sin 2* 的对话 UI + *AI 聊天界面*的亲和力

**核心视觉元素**:
- 屏幕下方为对话主面板：半透明深色底 + 柔和边框光
- NPC 对话以"角色名牌 + 头像框（占位 → 未来可替换 AI 生图）"形式呈现
- 玩家输入区采用聊天气泡风格，自由文本 + 快捷动作按钮并排
- AI 生成的建议动作以"可选卡片"形式漂浮在输入区上方（可点击填入）
- 关键叙事时刻：面板边框发光变色（金色=重要选择，红色=危险，蓝色=魔法/神秘）
- 环境背景在对话时略微虚化，突出面板

**情绪关键词**: 亲密、沉浸、对话感、选择的分量

---

### 锚点 C: 世界状态面板 — "记忆之网"

**参考作品**: *React Flow* 节点图 + *Disco Elysium* 思维阁 + *Persona 5* 的菜单美学

**核心视觉元素**:
- 角色关系图谱以节点-连线网络展示，当前角色居中
- 节点大小代表重要性/羁绊深度，连线颜色代表关系性质（绿=友好，红=敌对，灰=陌生）
- 世界书条目以卡片列表呈现，已解锁条目有插图占位（未来可替换 AI 生图）
- 记忆时间线：水平滚动的时间轴，关键事件以节点标记
- 整体采用暗色背景 + 高亮线条的风格化信息图美学

**情绪关键词**: ��控感、深度、连接、发现

## 5. 动词优先设计 (Verb-First Design)

> **动词优先原则**：先定义玩家能"做什么"，再推导实现这些动词需要什么系统。

### 核心动词表

| # | 动词 | 动词类型 | 触发方式 | 系统依赖 |
|---|------|---------|---------|---------|
| V1 | **探索 (Explore)** | 持续性 | 点击地图图块 | 地图系统、战争迷雾、区域事件 |
| V2 | **交谈 (Converse)** | 触发式 | 点击 NPC / 主动发起对话 | 对话系统、LLM、记忆引擎 |
| V3 | **检视 (Examine)** | 触发式 | 点击环境物件 / 输入"查看…" | 世界书、物品描述系统 |
| V4 | **使用 (Use)** | 触发式 | 从背包选择物品 → 选择目标 | 背包系统、物品效果解析器 |
| V5 | **抉择 (Decide)** | 关键节点 | AI GM 呈现选择项 | 分支追踪、后果系统、记忆引擎 |
| V6 | **收集 (Collect)** | 触发式 | 点击可拾取物品 | 背包系统、世界状态更新 |
| V7 | **旅行 (Travel)** | 持续性 | 点击区域出口/地图边缘 | 区域加载、随机遭遇、时间推进 |
| V8 | **回忆 (Recall)** | 随时 | 打开日志/世界书面板 | 记忆引擎、世界书 |
| V9 | **休息 (Rest)** | 触发式 | 点击安全区域（营地/旅馆） | 时间系统、状态恢复、事件推进 |
| V10 | **战斗 (Fight)** | 遭遇触发 | AI GM 宣告战斗 | 战斗系统（回合制叙事战斗） |

### 次要动词（Should Have / Could Have）

| # | 动词 | 描述 |
|---|------|------|
| V11 | **交易 (Trade)** | 与商人 NPC 买卖物品 |
| V12 | **制作 (Craft)** | 合并物品创造新物品 |
| V13 | **潜行 (Sneak)** | 避开敌人或不被注意地移动 |
| V14 | **说服 (Persuade)** | 通过对话改变 NPC 立场（检定系统） |
| V15 | **阅读 (Read)** | 阅读书籍/信件/碑文获取 lore |

## 6. 玩家心流模型 (Player Flow Model)

> 一个典型 60-90 分钟游戏会话的体验弧线。

```
体验强度
  ▲
  │                                          ┌──── 高潮：关键抉择或Boss战
  │                                     ╱    │
  │                                ╱         │
  │                           ╱              │
  │                      ╱                   ├──── 回落：后果消化，情感处理
  │                 ╱                        │
  │            ╱                             │
  │       ╱                                  │
  │  ╱                                       ├──── 钩子：新线索/悬念，引导下次会话
  │╱                                         │
  │────┬──────────┬──────────┬──────────┬────┤
  │    │          │          │          │    │
  │  入场      探索期     冲突升级    转折点  退场
  └──────────────────────────────────────────────▶ 时间
```

### 阶段详解

| 阶段 | 时长 | 玩家状态 | AI GM 行为 | 关键 UX |
|------|------|---------|-----------|---------|
| **1. 入场 (Re-Entry)** | 2-5 分钟 | "我上次在哪？现在该做什么？" | 呈现上回提要（3-5 条关键记忆），可选"完整回顾" | 会话恢复摘要面板 |
| **2. 探索期 (Exploration)** | 15-25 分钟 | 自由探索、熟悉环境、与 NPC 交谈 | 给予空间，偶尔提供环境描述和细微线索 | 地图导航、对话面板 |
| **3. 冲突升级 (Escalation)** | 20-30 分钟 | 主线/支线任务推进，遭遇挑战 | 引入冲突元素：敌人、谜题、道德困境 | 选择高亮、紧张感 UI 变化 |
| **4. 转折点 (Climax)** | 10-15 分钟 | 关键抉择或战斗 | 呈现核心冲突，要求玩家做出有分量的决定 | 全屏抉择面板、特殊音效/视觉 |
| **5. 回落与钩子 (Resolution + Hook)** | 5-10 分钟 | 消化后果，与 NPC 告别 | 给予情感收束，同时设下新悬念 | 日志更新动画、新区域/任务提示 |

### 心流调节机制

- **如果玩家探索时间过长无进展**：AI GM 推送一条温和的指引（"你注意到远处飘起一缕烟…"）
- **如果玩家连续高强度战斗**：AI GM 引导至安全区域，鼓励休息和对话
- **如果玩家在抉择时犹豫过久**：AI GM 不做催促，但维持紧张氛围（环境音效渐变）
- **会话时长软上限**：60-90 分钟时 AI GM 会寻找自然的"章节结束点"

## 7. 核心循环 (Core Loop)

```
         ┌──────────────────────────────────────┐
         │                                      │
         ▼                                      │
   ┌──────────┐                          ┌──────────┐
   │          │                          │          │
   │  探索    │──── 发现地点/NPC ──────▶│  互动    │
   │  EXPLORE │                          │ INTERACT │
   │          │◀─── 解锁新区域/线索 ─────│          │
   └──────────┘                          └──────────┘
        │                                      │
        │                                      │
        │     ┌────────────────────┐           │
        │     │                    │           │
        │     │   记 忆 引 擎     │           │
        │     │   MEMORY ENGINE   │           │
        │     │                    │           │
        │     │  实体提取│关系构建  │           │
        │     │  上下文检索│因果链  │           │
        │     └────────────────────┘           │
        │                                      │
        ▼                                      ▼
   ┌──────────┐                          ┌──────────┐
   │          │                          │          │
   │  成长    │◀─── 新物品/能力/知识 ────│  反馈    │
   │  GROW    │                          │ FEEDBACK │
   │          │──── 影响后续探索 ──────▶│          │
   └──────────┘                          └──────────┘
        │                                      ▲
        │                                      │
        └──────────────────────────────────────┘
```

### 循环分解

#### 阶段 1: 探索 (Explore)
- **输入**: 玩家点击地图图块移动角色
- **系统行为**: 地图系统计算可达路径、触发区域进入事件、揭示战争迷雾
- **输出到下一阶段**: 所处位置、可见 NPC、可交互物件列表

#### 阶段 2: 互动 (Interact)
- **输入**: 玩家发起对话 / 检视物件 / 使用物品
- **系统行为**: LLM 生成叙事回应（注入：当前区域 context + 相关记忆 + 世界书条目）、处理玩家意图
- **输出到下一阶段**: 叙事结果文本、状态变化指令、新信息

#### 阶段 3: 反馈 (Feedback)
- **输入**: 叙事结果 + 状态变化指令
- **系统行为**: 更新世界状态、触发 UI 响应（状态栏变化、日志条目、视觉特效）、记忆引擎提取并存储关键信息
- **输出到下一阶段**: 新的世界状态、可用的新能力/物品/知识

#### 阶段 4: 成长 (Grow)
- **输入**: 新能力/物品/知识 + 更新后的世界状态
- **系统行为**: 解锁新地图区域、开放新对话选项、角色属性提升
- **输出到下一阶段**: 扩展后的探索边界 → 回到阶段 1

### 外层循环: 会话循环 (Session Loop)

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│  开始会话    │────▶│  核心循环    │────▶│  结束会话    │
│  (加载世界   │     │  (30-90分钟) │     │  (记忆固化   │
│   状态)      │     │              │     │   悬念设置)  │
└─────────────┘     └─────────────┘     └─────────────┘
       ▲                                       │
       │                                       │
       └───────────────────────────────────────┘
               下次会话：恢复 + 新悬念推进
```

### 循环健康度指标

| 指标 | 健康阈值 | 风险信号 | 调节机制 |
|------|---------|---------|---------|
| 探索/互动比 | 1:1 ~ 2:1 | 连续探索 > 5 分钟无互动 | AI GM 推送环境事件 |
| 互动深度 | 每次互动 ≥ 1 个状态变化 | 连续 3 次互动无状态变化 | 引入有后果的选择 |
| 反馈延迟 | < 3 秒（叙事生成） | > 8 秒 | 流式输出 + 骨架屏 |
| 成长感知 | 每会话 ≥ 1 次可感知成长 | 连续 2 会话无成长 | 确保任务有明确奖励 |
| 记忆召回 | 每会话 ≥ 1 次过去事件被引用 | 连续 2 会话无记忆引用 | 增强记忆检索权重 |

## 附录 B: 与竞品的差异化总结

| 竞品 | 他们做什么 | 我们不做/不同 |
|------|-----------|-------------|
| RPG Roleplay Platform | Git 风格存档 + 世界书 | 我们有 2.5D 地图交互层，他们有 Git 存档（可能借鉴） |
| Narratium.ai | Worldbook + 视觉记忆管理 | 我们强调 AI 主动 GM 引导而非被动工具 |
| Arkyv Engine | 可视化世界编辑器 | 我们不要求玩家自己编辑世界，AI 代劳 |
| intra-game | 结构化游戏状态 + LLM | 相似的哲学，但他们侧重结构约束，我们侧重叙事涌现 |
| TaleWeave AI | prompt 生成世界 + 状态追踪 | 我们有 2.5D 地图作为差异化交互层 |
| Open Dungeon | 本地 LLM + 256K 上下文 | 我们用记忆引擎替代暴力上下文 |
| The Bunker | 确定性状态机 + LLM 配音 | 他们侧重确定性，我们拥抱涌现性 |

**我们的定位**：AI GM 驱动的单人叙事冒险，2.5D 地图增强空间沉浸，独立记忆引擎确保长程叙事质量。是"桌游主持人 + 视觉小说 + CRPG"三者的交集。
