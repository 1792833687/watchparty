## 1. UX 设计原则

> 以下原则派生自四大设计支柱和可访问性要求，是 UX 规格中每一个流程的检验标准。

| # | 原则 | 来源 | 含义 |
|---|------|------|------|
| **P1** | **GM 在场感** | 支柱 I | AI GM 始终有可见的状态指示（空闲/思考/说话/警告），玩家永远知道 GM 在做什么 |
| **P2** | **空间可触达** | 支柱 II | 地图图块的可交互性一眼可见，移动路径即时预览，不留"空白"交互区 |
| **P3** | **连续性不丢失** | 支柱 III | 进入/退出任何面板或模态，叙事上下文不丢失；会话恢复时有可读摘要 |
| **P4** | **选择可感知** | 支柱 IV | 关键抉择在视觉上不可忽视；选择后有明显反馈（状态栏动画、叙事后果文本） |
| **P5** | **渐进增强** | 架构原则 | CSS 优先渲染，动画可降级，所有信息至少有两个通道传达（颜色 + 形状/图标/文本） |
| **P6** | **无阻塞等待** | 心流模型 | LLM 调用期间提供流式反馈 + 骨架屏，不做空白等待；超时有清晰恢复路径 |
| **P7** | **可访问基线** | L2 Standard | 键盘完整导航、屏幕阅读器友好、色盲三通道、200% 缩放不丢内容 |

## 2. 全局状态模型

在展开各流程之前，先定义整个应用层的 UX 顶层状态机。

```
                    ┌─────────────┐
                    │   LANDING   │  ← 进入应用 / 会话结束后返回
                    └──┬───┬──────┘
                       │   │
          "开始新游戏"  │   │  "继续游戏"
                       │   │
              ┌────────▼───▼─────────┐
              │     SETUP            │  ← API Key 配置 + 模型选择 + 设定管理
              └──────────┬───────────┘
                         │ 设定就绪
                         ▼
              ┌──────────────────────┐
              │  CHARACTER_CREATION  │  ← 角色描述 → AI 生成 → 确认
              └──────────┬───────────┘
                         │ 角色确认
                         ▼
              ┌──────────────────────┐
              │   GAME_LOADING       │  ← 地图加载 + 记忆初始化 + 首条 AI 叙述
              └──────────┬───────────┘
                         │ 加载完成
                         ▼
              ┌──────────────────────────────────────────┐
              │              GAME_ACTIVE                  │
              │                                          │
              │  ┌─────────┐  ┌──────────┐  ┌────────┐  │
              │  │EXPLORING│─▶│DIALOGUING│─▶│DECIDING│  │
              │  └─────────┘  └──────────┘  └────────┘  │
              │       ▲             │            │       │
              │       └─────────────┴────────────┘       │
              │                                          │
              └──────────┬───────────────────────────────┘
                         │ 会话结束 / 异常退出
                         ▼
              ┌──────────────────────┐
              │   SESSION_CLOSING    │  ← 存档 + 摘要 + 钩子
              └──────────┬───────────┘
                         │
                         ▼
                    ┌─────────┐
                    │ LANDING  │  (循环)
                    └─────────┘
```

### 2.1 状态定义

| 状态 | 触发进入 | 可执行操作 | 退出条件 |
|------|---------|-----------|---------|
| **LANDING** | 首次访问 / 会话结束 | 开始新游戏、继续游戏、打开设置 | 进入 SETUP 或直接恢复 |
| **SETUP** | 用户选择"开始新游戏" | 配置 API Key、选择模型、导入/生成游戏设定 | 设定就绪 |
| **CHARACTER_CREATION** | 设定就绪 | 输入角色描述、AI 生成属性、确认 | 角色确认 |
| **GAME_LOADING** | 角色确认 / 读档 | 观看加载动画 | 地图+记忆+AI 就绪 |
| **GAME_ACTIVE** | 加载完成 | 探索/对话/抉择（核心循环） | 会话结束 / 异常 |
| **EXPLORING** (子状态) | 默认 / 移动完成 | 点击图块、查看地图、打开面板 | 进入对话/抉择 |
| **DIALOGUING** (子状态) | 图块事件触发 / 玩家发起对话 | 自由输入、点击建议动作、发送消息 | GM 回应完毕 |
| **DECIDING** (子状态) | GM 呈现 `[DECISION]` | 选择一个预设选项或自由输入 | 选项确认 |
| **SESSION_CLOSING** | 玩家点击结束 / 会话超时 / beforeunload | 存档、查看摘要 | 返回 LANDING |

| 场景 | 处理 |
|------|------|

| API Key 验证超时 (>10s) | "验证超时，请检查网络后重试" |
| 模型列表加载失败 | 使用内置静态模型列表 fallback，标注"离线模式" |
| 清除数据确认 | 二次确认 Modal："此操作不可撤销。确定清除所有存档和设置？" |

### 5.2 新手引导提示

#### 5.2.1 触发条件
- 首次新游戏（非读档）

#### 5.2.2 引导序列

新手引导采用**非阻断式**逐步提示（不冻结交互）：

| 步序 | 触发 | 提示内容 | 位置 | 持续 |
|------|------|---------|------|------|

#### 6.1.2 移动完整流程

```
触发条件: 玩家点击可到达图块

步骤 1: 路径计算 (同步，<50ms)
  ├── A* 寻路，计算最短路径
  ├── 如无路径 → 不响应 / 震动反馈
  └── 显示路径预览: 虚线从玩家位置延伸到目标 (SVG line, 300ms 绘制动画)

步骤 2: 移动执行 (300ms/格)
  ├── 玩家精灵沿路径逐格移动 (CSS transition)
  ├── 每进入一格: 战争迷雾揭示 (Canvas 绘制，<10ms)
  ├── 地图自动跟随 (camera 居中玩家)
  └── 移动中可中断: 点击新位置 → 重新寻路

步骤 3: 到达目的地
  ├── 检查图块事件 (on_enter / on_every_enter)
  │   ├── 有事件 → 触发对话
  │   ├── 无事件 → 保持 EXPLORING
  │   └── 有 Entity (NPC/物品) → 高亮 Entity + 显示交互提示
  └── 更新地图状态 (已探索标记)

步骤 4: 事件触发 → 对话
  └── 调用 dialogueSystem.sendMessage({type:'free_text', text:'', metadata:{clickedTileId}})
      → 进入 DIALOGUING 状态
```

#### 6.2.2 对话交互完整流程

```
触发条件: 玩家发送消息（自由文本 / 点击建议动作 / 地图事件触发空输入）

步骤 1: 输入处理
  ├── 自由文本: 输入框内容 + 发送按钮 / Ctrl+Enter
  ├── 建议动作: 点击卡片 → actionId 映射为文本 → 等同于发送该文本
  ├── 空输入（地图触发）: text='' → AI GM 主动叙述环境
  └── 输入验证:
      ├── 空文本（玩家手动发送空） → 不发送，输入框微震
      ├── >1000 字符 → 截断提示 Toast
      └── 连续发送 (300ms 内) → 防抖合并

步骤 2: AI 思考状态 (0-500ms)
  ├── 玩家消息气泡显示（右侧对齐，bg-input 背景）
  ├── 输入框禁用（灰色 + 锁图标）
  ├── AI 状态指示器: ◌ thinking (顶栏)
  ├── AI 头像脉动动画 (2s 周期)
  ├── 对话区底部 skeleton wave 光效
  └── 发送按钮变为加载动画

步骤 3: 流式接收 (500ms - ~5s)
  ├── 首 token 到达 → 创建 AI 消息气泡
  ├── 逐块渲染:
  │   ├── [NARRATIVE] → 叙述文本 (text-narrative 字体, 17px, 逐段淡入)
  │   ├── [ACTIONS] → 解析后在消息下方显示建议动作卡片
  │   ├── [STATE] → 等待全部消息完成后再触发 HUD 更新
  │   └── [DECISION] → 检测到即进入 DECIDING 状态
  └── 自动滚动到底部（如用户未手动上滚）

步骤 4: 完成处理
  ├── AI 状态指示器 → ◯ idle
  ├── 输入框恢复可用
  ├── HUD 状态栏更新（HP/MP/物品变化动画, stagger 100ms）
  ├── 如有位置变化 → 地图系统 moveTo()
  ├── 调用 memoryEngine.ingest() 存储对话
  └── 回到 EXPLORING 或进入 DECIDING
```

### 7.6 边缘情况

### 10.3 响应式切换过渡规则

| 过渡方向 | 行为 | 动画 |
|---------|------|------|
| Desktop → Tablet | 地图面板自动折叠 + 状态栏移至对话下方 | 地图滑出 300ms |
| Tablet → Desktop | 地图面板展开 + 三面板恢复 | 地图滑入 300ms |
| Tablet Landscape → Portrait | 从两面板切换为单面板 + TabBar | 交叉淡化 200ms |
| Portrait → Landscape | 从单面板恢复为两面板 | 交叉淡化 200ms |
| 任意 → Mobile | 单面板 + TabBar | 面板堆叠重排，即时 |

### 10.4 响应式降级的关键数据保持

| 降级中可能丢失的内容 | 保持策略 |
|---------------------|---------|
| 地图可见范围 | 记忆相机偏移和缩放级别，恢复时还原 |
| 对话滚动位置 | 记忆滚动位置（按消息 ID），恢复时滚动到相同位置 |
| 输入框中的未发送内容 | 存入 `localStorage` 草稿，切换面板后恢复 |
| 展开的面板状态 | Tab 选中状态持久化到 UIStore |
| AI 流式输出中途切换 | 流式输出继续（后台），切换回来时显示已接收内容 |
